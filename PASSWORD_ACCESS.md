# Вход без Google

Кабинет и реестр поддерживают почту + пароль приложения, а также Google.
Аккаунты Supabase общие с «Точкой дня»: существующие почта и пароль работают в обоих продуктах. Данные и локальные сессии приложений остаются раздельными.

## Первый доступ

Исполнитель входит в реестр → Ещё → Доступ студентов → Создать приглашение.
Указывает почту студента, копирует персональную ссылку и передаёт лично этому человеку.
Студент открывает ссылку, дважды вводит новый пароль и переходит в кабинет.
Ссылка — секрет доступа; не публиковать и не пересылать другим людям.
Письмо автоматически не отправляется. SMTP для этого сценария не нужен.

Сервер разрешает создание приглашений только подтверждённому аккаунту исполнителя из закрытой конфигурации. Для уже подтверждённого аккаунта возвращается existing; пароль и профиль не заменяются. Такой пользователь входит существующим паролем или Google. После входа через Google можно задать пароль в «Вход и синхронизация».

## Ограничения

Автоматическая отправка писем и самостоятельное восстановление забытого пароля по почте ещё не подключены. В интерфейсе об этом сказано: вход через Google, если доступен, либо обращение к исполнителю. Персональное восстановление требует проверки личности и отдельного административного действия, оно не выполняется кнопкой приглашения.
Смена пароля влияет на общий аккаунт, включая «Точку дня»; предупреждение показано до сохранения.

## Проверки

Node: ошибки входа освобождают busy; смена пользователя не разрешает автоматическую перезапись; приглашения закрыты от студента и невалидных адресов.
Chromium: форма почты/пароля на 390px; одна кнопка уведомлений до входа; активация использует oblako-kabinet, проверяет одноразовую ссылку один раз и допускает повтор сохранения пароля при ошибке.
Производственные аккаунты для тестирования не создаются; сквозной первый вход реального студента проверяется после выдачи ему приглашения.
