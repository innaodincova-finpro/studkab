# Серверный контур качества: эксплуатация и откат

Версия: 1.0. Миграция: `202609100001_quality_workflow.sql`.

## Граница этапа

Миграция добавляет модель, RLS, закрытый bucket и атомарный переход статуса. Она не подключает интерфейс и не меняет действующую выдачу. Флаг `studkab_workflow_config.enabled` после установки равен `false`.

## Серверные команды

Edge Function обязана проверить подтверждённую сессию, роль исполнителя из `studkab_executors`, входную схему и ожидаемую `revision`. Затем она выполняет операции с `service_role`, который никогда не попадает в браузер.

| Команда | Атомарный результат | Кто |
|---|---|---|
| `initialize_request` | `request_process` и первое событие | сервис после принятия заявки |
| `prepare_upload` | метаданные `uploading` и одноразовый путь | студент-владелец |
| `accept_upload` | проверенный MIME/hash, `accepted` либо `rejected` | сервис проверки файла |
| `submit_passport` | неизменяемая версия паспорта и пунктов | исполнитель |
| `approve_passport` | активный паспорт и переход `passport_approved` | исполнитель |
| `ask_clarification` | вопрос и `needs_information` | исполнитель |
| `answer_clarification` | ответ владельца без изменения паспорта | студент-владелец |
| `create_document_version` | снимок, DOCX, обе суммы | сервис/исполнитель |
| `record_checks` | результаты критериев конкретной версии | сервис/исполнитель |
| `approve_document` | утверждённая версия, если блокирующих ошибок нет | исполнитель |
| `deliver_document` | ровно утверждённый DOCX и `delivered` | исполнитель |
| `transition_request` | CAS-переход статуса и событие | сервер |

Клиент не пишет статусы, паспорта, критерии и версии напрямую. Идемпотентность команд обеспечивается идентификатором команды; это поле и журнал команд добавляются вместе с Edge Function перед подключением интерфейса.

## Файлы

Bucket `studkab-private` всегда private. Путь не содержит ФИО и темы: `request_uuid/file_uuid/version`. Перед созданием подписанной загрузки сервер создаёт строку `uploading`. Прямой `UPDATE` объекта запрещён: замена — новый `file_id` и новая версия. После загрузки сервис сверяет размер, сигнатуру MIME, контрольную сумму, лимит страниц и переводит файл из карантина. DOCX результата загружает только сервер.

## Безопасный выпуск

1. Снять и проверить резервную копию базы и метаданных Storage.
2. Применить миграцию к одноразовой базе PostgreSQL 16 и выполнить `tests/sql_safety.py`.
3. Применить миграцию к staging-проекту Supabase; проверить Auth и реальные Storage policies.
4. Развернуть Edge Function без маршрута из текущего UI.
5. Включить флаг только для тестового аккаунта, пройти UAT и сверить SHA-256 скачанного DOCX.
6. После UAT постепенно включать интерфейс. Общий флаг до этого остаётся выключенным.

## Откат

Операционный откат не удаляет таблицы и файлы:

```sql
begin;
update public.studkab_workflow_config
set enabled=false, pilot_student_ids='{}', updated_at=clock_timestamp()
where id=true;
commit;
```

После отключения возвращается предыдущая версия Edge Function/UI. Новые записи сохраняются для разбора и восстановления. `DROP TABLE`, удаление bucket и очистка файлов не входят в аварийный откат. Физическое удаление допускается отдельной согласованной миграцией только после экспорта, проверки сроков хранения и подтверждения отсутствия ссылок.

## Критерии допуска к интерфейсу

- миграция проходит два последовательных запуска теста на чистых базах;
- `anon` не читает ни одну новую таблицу или Storage;
- студент видит только свою заявку и только переданный документ;
- студент не может записать объект без заранее созданной строки `uploading`;
- исполнительская команда требует серверной роли и ожидаемой ревизии;
- запрещённый переход и гонка ревизий отклоняются;
- проверенный и скачанный DOCX имеют одинаковый SHA-256;
- отключение флага прекращает команды без удаления данных.
