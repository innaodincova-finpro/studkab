# A1 — протокол закрытого контура управляемых сбоев

Дата: 2026-09-13. Требования: R2–R4/R9, A1.2–A1.4.

## Граница безопасности

Испытание запускается только в одноразовом PostgreSQL-сервисе GitHub Safety. Оно
создаёт отдельную схему `studkab_a1_fault`; каждая запись имеет обязательный маркер
`A1-SYNTHETIC`. Контур не читает и не изменяет `public.studkab_gen_*`, не вызывает
production Edge Functions и не выполняет HTTP-запросы к AI-провайдеру. После прогона
схема удаляется независимо от результата.

## Сценарии и ожидаемые результаты

| Сценарий | Управляемый сбой | Критерий |
|---|---|---|
| A1.2 | `SIGKILL` отдельного процесса после сохранённого claim | просроченный claim заменён, старый fenced |
| A1.3 | два процесса одновременно запрашивают одну часть | ровно один claim, второй обработчик получает пустой ответ |
| A1.4 | синтетический провайдер сохраняет квитанцию, процесс завершается до settle | одна попытка и одна квитанция, часть `unknown`, повторной отправки нет |

Команда CI: `node tests/a1-fault-injection.mjs` после создания PostgreSQL service.

## Фактический результат

На момент добавления протокола код подготовлен. Номер Safety run, commit и фактический
вывод заполняются только после выполнения отдельного PR. До зелёного CI A1.2–A1.4
остаются неподтверждёнными этим контуром.

## Ограничение доказательства

Контур проверяет реальную остановку процесса, конкурентные процессы и сохранённую
квитанцию после отправки на изолированном серверном хранилище. Он не является
отключением размещённого Supabase Edge runtime и не доказывает сбой внешней сети.
Такое production-испытание потребовало бы отдельного развёрнутого проекта/ветки и
явного управления инфраструктурой; пользовательская очередь для него не используется.
