# C124 — уведомления после длительного сбоя

Требования: MVP M4, TASK R2/R9. В рабочей базе подтверждено: после четырёх неудачных попыток Web Push или восьми попыток Telegram непрочитанное событие диалога больше не выбирается для отправки.

Решение: миграция `20260926161000_c124_dialog_retry.sql` оставляет прежний предел для напоминаний о сроках и продолжает попытки для непрочитанных событий диалога с паузой до часа. Подтверждённые отправки и прочитанные события повторно не выбираются. Рассматривались сохранение предела и ручной сброс; оба оставляют возможность незаметно потерять сообщение.

Сохраняются существующие данные, права ролей и бесплатное расписание. Нет платных вызовов и изменений заявок. Ограничения: Web Push требует действующей подписки; при принятом Telegram сообщении и потерянном подтверждении строго однократную доставку гарантировать нельзя.

Проверка: `tests/dialog-events.test.mjs` проверяет повтор после прежних пределов, остановку после подтверждения и прочтения, права доступа и предел напоминаний. Рабочую доставку двух ролей проверить отдельно после установки. Откат: вернуть определения двух RPC из предыдущих миграций, не удаляя события и записи отправки.

Полный исторический журнал изменений остаётся в `CHANGE_CONTROL.md` без повторной передачи его содержимого через интеграцию GitHub: автоматическая проверка отклонила такую передачу как потенциально чувствительную. Эта короткая запись документирует весь состав C124 для публичного ревью.
