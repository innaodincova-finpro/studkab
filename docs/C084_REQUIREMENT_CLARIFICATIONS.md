# C-084: уточнение и проверка требований

## Сценарий
Исполнитель открывает «Требования → Вопросы студенту», выбирает пункт и сохраняет вопрос.
Студент открывает свою работу → «Открыть вопросы и ответы», вводит ответ и основание.
Исполнитель открывает «Новая версия», сверяет ответ, записывает точное требование,
указывает источник и отмечает проверку. Сохранение создаёт отдельный проект паспорта.
Утверждение выполняется отдельно. Вопросы без ответа и ответы без проверки блокируют его.

Вопрос появляется в кабинете при открытии списка. Email/Telegram-уведомление
этим изменением не добавляется. Ответ — текст и ссылка/описание основания до 1000 знаков;
загрузка нового файла в этот путь пока не входит. Материалы C-080 не перезаписываются.
Сохранённый ответ нельзя исправить задним числом; исполнитель задаёт новый вопрос.

## Защита
- Edge проверяет подтверждённый вход, роль исполнителя или членство и владельца заявки.
- Новая таблица закрыта от anon/authenticated; RLS включён, RPC разрешены service_role.
- SQL повторно проверяет автора по auth.users и конфигурации, владельца/членство студента.
- Вопрос и утверждение блокируют одну строку заявки: новый вопрос снимает прежнее утверждение.
- Повтор одного questionId с тем же текстом и повтор точного ответа идемпотентны.
- При утверждении проверяются последняя ревизия, точные пункты, отпечаток, обязательные
  идентификаторы, явная отметка verified и непустое основание. Флаг required=false
  не отменяет обязательные стандартные пункты. Поиск слов оставлен дополнительной защитой.
- Каждый ответ должен быть связан с соответствующим пунктом этой заявки; паспорт
  должен быть сохранён после ответа. Изменение материалов снимает отметки проверки в новой версии.
- При смене аккаунта открытый редактор/диалог не записывает данные от прежней роли.
- Проверка не устанавливает истинность произвольного текста: за содержательную проверку
  отвечает исполнитель, её отметка и источник сохраняются в версии паспорта.
- Ранее утверждённые паспорта не массово изменяются миграцией. Новое утверждение проходит
  усиленную проверку; новый вопрос снимает прежнее утверждение именно своей заявки.

## Установка и откат
1. Проверить CI (Node, SQL replay, браузер) и совместимость с текущей main.
2. Применить только миграцию 20260921165603_c084_requirement_clarifications.sql.
3. Установить Edge studkab-requests из той же версии.
4. Опубликовать frontend и sw.js с cache v73.
5. На тестовой заявке выполнить полный путь двумя ролями, проверить чужую заявку,
   повтор после потери ответа, запрет утверждения до проверки и сохранность старой версии.
   Не использовать реальных студентов, не выполнять платную генерацию и передачу документа.

Не объединять до шага 2: main автоматически публикует frontend/Edge. Старый frontend
после установки SQL может получать отказ утверждения — это ожидаемое безопасное состояние.
Откат frontend/Edge допускается без удаления новой таблицы и записей. Усиленную SQL-защиту
не снимать; исправлять вперёд. Граф удаления C-079/C-080 включает новые уточнения и их счётчик.
