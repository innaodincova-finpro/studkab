# C177 — доказательства расчётов и страниц Word: техническое решение до реализации

Дата: 29.09.2026. Статус: анализ подтверждён кодом и контрактом; новый внешний обработчик и положительные допуски **не утверждены и не установлены**. Основание: TASK R14/R13, QUALITY_DOCUMENT_CONTRACT QD01–QD07, AGENTS.md. Это не приёмка STUDKAB.

## Что установлено в текущем коде

1. `reviewPacket` в `supabase/functions/studkab-generation-api/review-pass.mjs` получает точные байты DOCX, проверяет хеш, но передаёт помощнику извлечённый текст основного тела документа. `inspectWord` не вычисляет фактические страницы и не рендерит таблицы, шрифты и поля. Заголовки, сноски и изображения не входят в этот текстовый проход.
2. Паспорт содержит свободный текст условий и ссылку на материал. Для произвольной заявки в нём нет обязательного полного перечня формул, исходных значений, единиц, периодов, правил округления и контрольных результатов. Один верный пример вычисления не доказывает, что выполнены все расчёты.
3. C177 принимает положительное текстовое свидетельство только через завершённую проверку точной версии Word. Пункты о расчётах и визуальных условиях теперь блокируются в текстовом проходе, в том числе при произвольном ID. Положительного проверенного пути для них нет. Миграция C177 поэтому остаётся только в draft PR #193.

## Проверяемый маршрут расчётов

Для каждого расчётного условия паспорт должен перечислять требуемые показатели/операции без универсального шаблона для всех дисциплин. Для каждого показателя проверяющий помощник предоставляет точный источник и место числа, период, единицу, формулу, правило округления, место результата в текущем Word и объяснение метода. Сервер независимо пересчитывает только поддерживаемые формулы и сверяет исходные числа с неизменёнными материалами, а результат — с точным Word. Неподдерживаемая методика, пропущенный показатель, несовпадение единицы/периода, ошибка округления или неразрешённое противоречие остаются `not_checked`/`fail`; часть верных формул не превращается в `pass` для всего условия. Для иных дисциплин нужны отдельные проверяющие модули либо предметная проверка помощником с честно указанным пределом; FIN-UAT-01 не становится шаблоном.

Первый кодовый срез: структурированная опись расчётных требований и безопасный пересчёт ограниченной арифметики из исходных чисел. Положительный допуск общего `CALCULATIONS` включать только после доказательства полноты описи и сквозного теста Edge → БД → выдача для точной версии. Платные вызовы только через действующие смету и лимит; синтетические тесты без API-расходов.

## Проверяемый маршрут страниц

Нужен доверенный обработчик, который берёт сохранённые байты DOCX по хешу, создаёт страницы, сохраняет версию средства/шрифтов, число страниц и хеши изображений и передаёт их визуальному проверяющему помощнику. Отчёт связывается с заявкой, паспортом, исходными байтами и каждой просмотренной страницей; изменение хотя бы одного байта Word обнуляет допуск. Неотображённая страница, обрезанная таблица, неизвестный шрифт, сбой конвертации или расхождение с требуемым Microsoft Word оставляют условие открытым. PDF/скриншот, присланный браузером, без серверного доказательства происхождения не подходит.

Текущая Supabase Edge Function ограничена 256 МБ памяти и 2 секундами процессорного времени на запрос; полноценный рендер произвольного DOCX в ней не реализован и его работоспособность не подтверждена. См. [действующие лимиты Supabase](https://supabase.com/docs/guides/functions/limits). Возможный отдельный процессор — приватный контейнер с конвертером и нулём постоянно работающих экземпляров; [Cloud Run поддерживает пользовательские бинарные пакеты](https://docs.cloud.google.com/run/docs). Это лишь кандидат: конвертация LibreOffice сама по себе не равна просмотру в Microsoft Word. [Microsoft Graph умеет получить PDF из DOCX](https://learn.microsoft.com/en-us/graph/api/driveitem-get-content-format?view=graph-rest-1.0), но требует отдельной авторизации и передачи файла в Microsoft Cloud; её точность и доступность для STUDKAB не проверены.

## Граница решения и приёмка

Перед добавлением внешнего обработчика нужно согласовать поставщика, передачу студенческих файлов, хранение и удаление промежуточных копий, доступы и лимит расходов. Cloud Run имеет [бесплатный объём и тарификацию сверх него](https://cloud.google.com/run/pricing); [ограничение расходов для Cloud Run существует в предварительном выпуске](https://docs.cloud.google.com/billing/docs/how-to/budgets-spend-caps), с задержкой срабатывания и возможным превышением. Бесплатность конкретной нагрузки не установлена. Текущая архитектура по AGENTS.md допускает новый стек только после документированного обоснования. Развёртывание и платные пробы до решения не делать.

Приёмка будущего маршрута: несколько работ разных типов; неверная формула при правильном тексте; верная одна формула при пропуске другой; числа и период из другого источника; обрезанная таблица; изменённый DOCX после проверки; недоступный рендер; чужой пользователь; потерянный ответ и повтор. Для каждого случая нужны точные входные версии, ожидаемый и фактический допуск, хеши, предел расходов и доказательство просмотра каждой страницы. Автоматический тест и конвертация не заменяют предметную приёмку и независимую оценку по QD07.
