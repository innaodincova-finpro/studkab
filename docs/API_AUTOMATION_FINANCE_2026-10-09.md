# Автоматическая подготовка и контроль расходов STUDKAB

API-FINANCE-01. Исследование и контракт внедрения 09.10.2026.
Цель: исполнитель видит доступные инструменты; приложение передаёт все оригиналы
и автоматически возвращает работу с комментарием. Чат — запасной ручной способ.
Платные проверки этим этапом не разрешены.

## Фактическая готовность

Текущий код содержит серверный запуск, бюджетные ограничения, диагностику
подключений и ручные комплекты для трёх нейросетей. Это не доказывает реального
успешного выполнения через API. Общего законченного учёта балансов и сверки
расходов всех трёх поставщиков пока нет. Проверка конфигурации или модели
не является выполнением задания либо проверкой баланса поставщика.

## Разные суммы

| Величина | Источник | Назначение |
|---|---|---|
| Баланс поставщика | Его API или кабинет | Деньги на его счёте |
| Бюджет приложения | Политика владельца | Разрешённые расходы STUDKAB |
| Резерв | Учёт попыток | Защита параллельных и неопределённых запусков |
| Расчётная стоимость | Usage ответа и тариф | Оперативный расход попытки |
| Сверенный расход | Отчёт поставщика | Подтверждение начисления |

Резерв не называть списанием. Баланс не вычислять из пополнения минус расходы
STUDKAB: возможны другие приложения, кредиты и задержки. Неизвестный баланс
не обозначать нулём. CNY/USD хранить отдельно, без выдуманного курса.

## Официальные возможности

DeepSeek: GET /user/balance возвращает доступность и остаток по валютам,
включая пополненные и предоставленные средства. Проверяется сервером действующим
ключом без генерации. Files API принимает изображения JPEG, PNG, GIF, WebP;
он не решает передачу PDF/Word в текущий адаптер.

OpenAI: GET /organization/costs предоставляет расходы с суточными интервалами
и группировкой по проекту. Административные операции требуют соответствующего
доступа, обычный рабочий ключ не считать заменой. В проверенных источниках
универсальный публичный endpoint остатка предоплаченного кошелька не установлен:
до подтверждения применимого API показывать отсутствие автоматической проверки
баланса и ссылку в кабинет. Документация предусматривает жёсткие месячные
пределы организации/проекта, но предупреждает о задержке применения и небольшом
превышении. Уведомление о расходах само по себе предел не устанавливает.
Responses API принимает PDF/DOCX; в non-PDF документах встроенные изображения
и графики не попадают в контекст. Поддержка формата не гарантирует полноту.

Claude: Usage and Cost Admin API даёт исторические данные организации;
индивидуальным аккаунтам недоступен, нужен допустимый административный доступ.
Данные обычно появляются в течение пяти минут, иногда позже; расходы
имеют суточные интервалы. Это не подтверждённый endpoint остатка кошелька.
Документный блок поддерживает PDF/текст; DOCX/XLSX требуют другого пути.
Файловый/инструментальный маршрут надо отдельно реализовать и проверить;
наличие Files API не означает готовность текущего адаптера.

Отсутствие API проверки кошелька Claude/OpenAI само по себе не блокирует
исправное подключение: учитываются бюджет и ошибки поставщика, баланс неизвестен.
Положительный DeepSeek balance не гарантирует средств на весь запрос.
До оплаты проверяется приём полного комплекта выбранной моделью.
Пропуск файлов и молчаливое извлечение текста запрещены. Дополнительные
представления документов требуют решения с сохранением оригиналов.

## Автоматический процесс

1. Владелец устанавливает поставщиков/модели, числовой предел заявки,
   суток и месяца, платные инструменты и резервный способ. Без проверяемого
   разрешения платный запуск запрещён. Автопополнение по умолчанию выключено.
   Подписку чата не считать оплатой API.
2. Сервер фиксирует все оригиналы, версию/хеши, сведения титульного листа,
   запрос на работу и комментарий. До оплаты проверяет доступ, полноту,
   форматы, ограничения и прежние попытки. Внутреннего OCR допуска нет.
3. По версии тарифа, входу, максимально разрешённому выходу и платным
   инструментам рассчитывает доказуемый потолок. Неизвестный потолок
   блокирует запуск. Прогноз не называется точным будущим списанием.
4. Атомарно проверяет предел заявки/суток/месяца и резервирует потолок.
   Намерение запуска и версия комплекта имеют устойчивый ключ.
   Повторный клик и два обработчика не создают второй платный запуск.
5. Сохраняет попытку до отправки; обработчик отправляет оригиналы, фиксирует
   идентификатор поставщика и состояние. Работа и возврат продолжаются
   после закрытия браузера. Ключи только на сервере.
6. Сохраняет usage, стоимость, работу и комментарий; формирует файл
   и возвращает в ту же заявку/версию. Сбой сохранения повторяет
   сохранение результата, а не платную генерацию.
7. Освобождает доказанную неиспользованную часть резерва по правилам учёта,
   сверяет расход с отчётом. Корректировки отдельными записями; история
   попытки, тарифа и сверки не переписывается.
8. Исполнитель проверяет работу и комментарий и передаёт студенту.
   Ответ нейросети не доказывает правильность и не означает выдачу студенту.

Внутри явно разрешённой политики автоматизации не требуется повторное
согласование каждой заявки. Превышение ждёт решения или ручного способа.
Текущий механизм подтверждения цены сохраняется до реализации такой политики.

## Восстановление

Таймаут после отправки может оставить неизвестными результат и начисление.
Резерв сохраняется; сначала проверяются существующая попытка и отчёт.
Повтор/переключение поставщика запрещены, пока возможна двойная оплата.
Не предполагать поддержку idempotency у поставщика без подтверждения.
Повторы неотправленного запроса и неоплачиваемой диагностики ограничены.

Недостаток средств одного способа не блокирует независимые доступные способы.
До отправки резервный выбор возможен по разрешённой политике и полному покрытию
файлов; после неопределённой отправки — сверка. Неполный ответ не называется
готовой работой. Исправление имеет отдельную возможную стоимость в пределе заявки.

## Интерфейс и свежесть информации

Карточка: способы конкретного комплекта, действие, короткое состояние и следующий
шаг; если требуется решение об оплате — предельная цена. При блокировке —
подключить, пополнить, открыть расходы или идти в чат. Без инженерных абзацев.

Отдельный раздел «Подключения и расходы» для владельца: поставщик/модель,
доступность, баланс с валютой/источником/временем либо отсутствие данных,
бюджет, резерв, расчётные и сверенные расходы, история по заявкам,
предупреждения и ссылки в кабинеты. Исполнителю — только разрешённый доступ.

Предлагается проверять подключение при открытии раздела и перед запуском,
DeepSeek balance до запуска и после результата с кэшем и ограничением частоты.
Отчёты опрашиваются фоном в пределах документации. Каждый источник имеет
своё время проверки. Сбой сохраняет последнее значение как устаревшее.
Стоимость обновляется после usage, сверка — после отчёта. Это контракт,
не действующая настройка. Пороги предупреждений и каналы задаёт владелец;
отключённый email не считать работающим.

## Этапы внедрения

A. Без оплаты: отдельные поля/время источников, read-only adapters баланса/отчётов,
unknown/stale/permission denied. Не создавать ключи. Сверить существующие
резервы, не обнулять и не повышать лимиты.

B. Согласовать картинки «сейчас / станет» карточки, подключений, расходов
и результата. Затем внедрить UI-CONCEPT-01 для обоих кабинетов.

C. Подключить политику расходов, обработчик полного комплекта, резерв/расчёт/сверку
и независимый возврат. Неоплачиваемые проверки с контролируемыми поставщиками,
один полный Safety перед merge. Тестовые ответы не являются реальной приёмкой.

D. Только после отдельного решения о допустимом реальном расходе: существующая
заявка → весь комплект → работа/комментарий → автоматическое вложение →
usage/стоимость/сверка → проверка исполнителем → передача. Платных проб сейчас нет.

Проверки: двойной клик/параллельные задания; неизвестный/пустой баланс; запрет
бюджета; неизвестный тариф; неподдержанный файл; старый комплект; таймаут
до/после отправки; неполный ответ; сбой сохранения; повтор возврата; задержка
отчёта; смена аккаунта; закрытие браузера; отсутствие административных прав.
Существующая инфраструктура сохраняется. Откат не удаляет заявки, оригиналы,
попытки и финансовую историю; миграции совместимы.

## Реализация этапа A от 09.10.2026

Новый assistant-finances доступен только подтверждённому исполнителю через
существующий authenticated requests handler. Возвращает текущий доступный бюджет
приложения отдельно от balance/costs поставщиков. Значения резервов и фактические
списания отдельных заявок этот endpoint пока не выдаёт. Не называть этап полным
финансовым учётом. В рабочий интерфейс новый endpoint ещё не подключён.

DeepSeek баланс проверяется через существующий Worker с действующим DEEPSEEK_KEY;
флаги генерации не включаются, prompt не отправляется. OpenAI использует
OPENAI_ADMIN_API_KEY и STUDKAB_ASSISTANT_OPENAI_PROJECT_ID; Claude —
ANTHROPIC_ADMIN_API_KEY и STUDKAB_ASSISTANT_CLAUDE_WORKSPACE_ID. Эти значения
только читаются на сервере при наличии; отсутствующие ключи не создаются.
Обычные runtime keys не подставляются как admin keys. Claude отчёт сначала
группируется по workspace и на сервере остаётся только заданный workspace;
работа с default workspace требует отдельного явного выбора и пока не включена.

Период — текущий календарный месяц в UTC, отчёты суточные; это показания
поставщика в доступных buckets, не моментальный баланс. Claude Priority Tier
не включён. Пагинация до четырёх страниц; неполный отчёт остаётся unknown.
Резерв и разрешённый лимит отчётами не меняются. Проверки объединяются на
одном Edge instance, кэш60с; сбой сохраняет последний успех как stale максимум
10мин, затем unknown. Это не глобальный scheduler и не долговременный журнал.
Ответы имеют source, checkedAt, observedAt и период; произвольные ответы/ошибки
и ключи не выдаются. Оплата, пополнение, изменение лимитов и inference не вызываются.
