# AUTO-ASSISTANT-01 — автоматическая подготовка по выбранному способу

Статус: контракт подготовлен по прямому требованию 08.10.2026; интеграция не реализована и не принята.

## Результат пользователя

В карточке три равноправных способа: Claude, ChatGPT/Codex, DeepSeek. Нажатие на доступный способ запускает подготовку существующей заявки: документы, сведения для титульного листа, требования и замечания передаются автоматически; готовый файл возвращается в ту же заявку автоматически. До запуска показывается нейтральное «Выберите помощника». При недоступности способа видна конкретная причина; нет кнопки, обещающей запуск и только меняющей локальный выбор. При необходимости нового платного согласования запуск явно приостановлен до него.

## Подтверждённые пробелы

| Способ | Сейчас | Требуется |
|---|---|---|
| Claude | Копирование документов в таблицы; запуск по сообщению в чужом чате; результат прикрепляется при следующем открытии карточки | Подключённый обработчик, автоматический запуск и возврат файла без открытия карточки |
| ChatGPT/Codex | Копирование запроса, открытие chatgpt.com, ручные документы/результат | Программное подключение, автоматические документы/задание и возврат файла |
| DeepSeek | Серверная очередь подготовки частей; применение текста/экспорт через редактор; внутренний бюджет блокирует запуск | Проверка бюджета, автоматический полный документ с вложением в заявку |

Заголовок сейчас учитывает прежнюю очередь Claude, но не выбор. Нельзя исправить это простым присвоением выбранного названия: оно будет ложно описывать уже выполняющееся задание. Серверное активное задание — источник статуса; локальный выбор — намерение следующего запуска.

## Общий контракт

1. Перед запуском сервер проверяет роль исполнителя, существующую заявку, доступность выбранного подключения и разрешённый лимит. Проверка конфигурации не называется успешной проверкой реального выполнения.
2. Сервер сохраняет выбранного помощника и снимок комплекта: все действующие вложения, хеши, версия заявки, требования, сведения титульного листа и замечания текущего круга. Необработанный/неподдерживаемый файл не пропускается молча: видна причина и потребность в уточнении.
3. Один повторный клик/потеря ответа не создаёт второй платный запуск. При существующем активном задании показывается его состояние; изменение выбора его не отменяет и не переименовывает. Материалы/предыдущие результаты сохраняются.
4. Обработчик автоматически получает документы и запускает выбранный способ. Состояния: проверка → очередь → подтверждённое выполнение → формирование документа → файл готов; отдельно ошибка/лимит/требуется уточнение. Начало выполнения требует подтверждения обработчика.
5. Автоматически формируется и проверяется готовый файл Word с корректными сведениями, разделами, расчётами/источниками там, где они требуются. Набор частей или текстовый ответ не называется готовой работой.
6. Файл сохраняется сервером в существующее хранилище результата с проверкой типа, размера, хеша и принадлежности заявке. Возврат не зависит от открытого браузера. После перезагрузки карточка показывает тот же результат.
7. Исполнитель проверяет работу и передаёт студенту существующим маршрутом. Автоматическое возвращение в заявку не означает передачу студенту или сдачу преподавателю.
8. При смене аккаунта ответ не попадает в чужую карточку. При изменении материалов результат связан с прежней версией. Повторы после неопределённого ответа не обходят бюджет и не запускаются бесконтрольно.

## Подключения и инфраструктура

Предпочтительный вариант без нового стека: действующие Supabase/Edge и Cloudflare получают серверные адаптеры программных API Claude и OpenAI, общий ограниченный бюджет и серверное формирование Word; DeepSeek использует существующий посредник. Это отдельное подключение поставщиков, а не открытие обычных чатов. Требуются проверенные серверные credentials, явно разрешённые расходы и совместимая модель обработки всех типов вложений. Наличие credentials не проверено; новые платные вызовы не выполнялись.

Альтернатива для Codex: официальный app-server/SDK с управляемой авторизацией ChatGPT. Для Claude: Agent SDK в управляемом процессе с допустимой авторизацией. Эти варианты требуют постоянного обработчика, которого в проверенном репозитории нет; новый runtime требует обоснования/согласования по AGENTS.md. Доступ текущего чата к аккаунту не доказывает, что приложение располагает таким подключением. Нельзя обещать автоматическую отправку в произвольный обычный чат по URL.

Официальные материалы, прочитанные 08.10.2026:

- https://learn.chatgpt.com/docs/codex-sdk — программное управление агентами.
- https://code.claude.com/docs/en/agent-sdk/overview — агент в управляемом процессе; ограничения встроенного входа claude.ai для сторонних продуктов.
- https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan — текущие условия использования подписки/кредитов; применимость к конкретному аккаунту отдельно проверяется.

## Бюджет и реальная приёмка

База на момент аудита: общий предел $10; временный предел $1.07; резерв/учтённые суммы $1.15729; доступно 0. Не повышать предел и не освобождать резерв ради обхода блокировки. Для решения сначала сопоставить резерв с состояниями реальных заданий/правилами учёта; нет оснований автоматически считать резерв свободными деньгами.

Дополнительная сверка: в текущей studkab_gen_attempts нет строк, поэтому сумму reserved_microusd нельзя объяснить по этой таблице. Причина расхождения не установлена; это не разрешение обнулить резерв или поднять предел. Требуется сверка с журналом учёта/историей конфигурации.

Проверка каждого способа: настоящая существующая заявка → все документы получены выбранным обработчиком → подтверждённый запуск → готовый файл автоматически в заявке → перезагрузка/возврат без повторного списания → проверка исполнителем → передача студенту. Отдельно потеря ответа, двойное нажатие, закрытие браузера/восстановление обработчика, смена аккаунта, изменение материалов, блокировка бюджета и ошибка поставщика. Один полный Safety перед merge; подставные тесты не заменяют эту приёмку.

До написания UI подготовить «сейчас / станет» по ROUTE-03. Публикация документации не означает реализацию. Никакие пользовательские заявки или файлы аудитом не изменялись.
