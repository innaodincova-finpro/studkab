# C177-P7 — два прохода проверки содержания

TASK R4/R5/R7/R8/R14, пункт 2 сохранённого плана. Новый запуск проверки точного Word создаёт два последовательных задания существующего помощника на одном серверном пакете материалов и паспорта. Первый собирает свидетельства; второй заново сверяет материалы, Word и сохранённый первый отчёт. Это проверка выводов тем же провайдером, а не гарантия независимости двух экспертов.

Первый отчёт полностью сохраняется. До второго платного вызова сервер проверяет его формат, хеш и цитаты. Неверный первый отчёт блокируется до dispatch, неизвестный результат любого прохода не повторяется автоматически. Смета включает оба вызова и верхнюю границу сохранённого контекста; потолки работы и общего бюджета не увеличиваются. Платные вызовы при разработке не выполнялись.

Положительный пункт второго требует проверенного положительного пункта первого. Сервер сохраняет замечания обоих; SQL отдельно требует два завершённых согласованных результата той же версии. Ошибка первого не исчезает из допуска из-за чистого второго отчёта. Однопроходные отчёты читаются как история и не создают новые положительные свидетельства двухпроходной проверки. Не изменяются прежние выдачи и исходные байты. Интерфейс показывает оба этапа, сохранённый первый отчёт и общий резерв стоимости.

Локально прошли 57 тестов API, 21 тест обработчика, два теста передачи замечаний и SQL-проверка. Общий набор: 15 предварительных и 556 основных тестов прошли; после уточнения запрета восстановления повторены адресные SQL и проверка истории миграций. Браузерные сценарии подготовлены и их загрузка проверена, фактическая браузерная проверка этой версии ещё не проведена. CI, установка и предметная приёмка остаются отдельными шагами. Два прохода не подтверждают полные расчёты, фактические страницы Microsoft Word или подлинный внешний отчёт: эти условия остаются блокерами.

Установка должна сохранить порядок БД → совместимые API/обработчик → интерфейс. Откат должен одновременно вернуть согласованный API и серверный допуск, удерживая выдачу по неподтверждённым новым заданиям; историю не удалять. Новые helpers доступны только service_role; клиенту прямой RPC-допуск не добавляется.
