# Исправление замечаний аудита — 7 сентября 2026

Статус: кандидат на проверку, не рабочий релиз.
Исходник: studkab-audit.zip; index.html, reestr.html, sw.js совпадают по Git blob SHA с main d218e422edc2fd2ea2afe5ff4036ee33d4809a35; облачный модуль также сверён.

## Внесено
- Запись заблокирована до чтения и явного выбора данных; отказ от переноса не включает автозапись.
- Конфликт не присваивает локальным данным чужую версию; явная замена также проверяет версию.
- Параллельные запросы сохранения одного клиента не отправляются одновременно.
- Настройки и справочники при пустом списке заявок не считаются отсутствующей строкой.
- Сообщения об успехе зависят от ответа базы и успешного применения локальной копии.
- Идентификаторы и опасные ключи проверяются до импорта/применения облачных данных.
- Локальные данные аккаунтов используют отдельные ключи; история отмены очищается при смене.
- Пароль посредника удаляется из отправляемой копии и входящей облачной копии; локальное значение сохраняется.
- Очистка кэшей ограничена именами studkab-vN; адрес облачного модуля версионирован.
- Новая RPC save_app_data_v2: создание только при rev=0; обновление атомарно сравнивает rev.
- Старый облачный API блокирует кабинет/реестр: старая вкладка не должна обходить новую логику.

## Подтверждено локально
`node --test tests/safety.test.cjs`: 20 успешных тестов. Это тесты JavaScript с имитацией ответов сервера, включая синтаксис обеих страниц, а не полноценная браузерная приёмка.

## Автоматизация
Safety checks запускает те же тесты и tests/sql_safety.py на отдельном PostgreSQL 16.
SQL-тест проверяет конкурирующее создание и обновление, права другого пользователя, удаление секрета и блокировку старого API. Скрипт нельзя направлять в рабочую базу.

## Условия выпуска — пока не подтверждены
- Успешный SQL-тест CI.
- Браузер: вход A → изменение → обновление страницы → выход → вход B → возврат A; несохранённые правки и гостевые записи должны сохраняться в своём контуре.
- Браузер: отказ localStorage, потеря сети, восстановление копии, Word, узкий экран.
- Снимок только строк/функций платформы в рабочей базе и пробное восстановление в изолированной среде.
- Проверка реальных прав app_data и отсутствия сторонних потребителей старой RPC; база используется совместно.
- Установка cloud-safety.sql и проверка новой RPC перед публикацией фронтенда. Код базы в архиве не доказывает настройки работающей базы.
- Проверка публикации и уже установленного приложения после обновления.

## Ограничения
Разделение ключей не изолирует приложения одного домена от произвольного JavaScript: отдельный origin остаётся необходимым для полноценного разделения. Старые локальные данные без владельца привязываются к первому вошедшему аккаунту на устройстве; до миграции владельца нельзя доказать по прежнему формату. Пароли, ранее попавшие в облако/историю резервирования, этой правкой задним числом не очищены: требуется отдельно проверить и сменить секрет посредника. SQL не применялся к рабочей базе. Доставку писем, Worker, документы и мобильный маршрут эта проверка не подтверждает.

## Возврат при сбое
Не возвращать старую небезопасную RPC ради восстановления автозаписи. Сохранить локальные данные; остановить выпуск и устранять сбой в отдельной ветке. Возврат данных — только из проверенной копии с сопоставлением владельца и приложения.
