# Защита main и безопасный откат

Состояние на 13.09.2026: файл фиксирует обязательную конфигурацию. Само наличие
этого файла не означает, что административные правила GitHub уже включены.

## Обязательный ruleset GitHub

Создать ruleset для ветки `main` со статусом **Active**:

- запретить удаление ветки и force push;
- требовать Pull Request перед объединением;
- требовать успешную проверку `safety`;
- требовать актуальность ветки относительно `main` перед объединением;
- не разрешать обход правил обычным участникам;
- не разрешать прямые commits в `main`.

Для одиночного владельца допустимо 0 обязательных одобрений: защитой служат PR,
актуальная ветка и зелёный `safety`. После появления независимого проверяющего
установить минимум 1 одобрение.

## Что проверяет workflow

`Safety checks` запускается для каждого Pull Request и каждого push в `main`.
Он выполняет проверку названий commits, Node, PostgreSQL, Chromium и WebKit.
Стандартное сообщение GitHub `Add files via upload` запрещено.

Push-проверка является сигнализацией после факта и не заменяет ruleset. Только
ruleset технически не допускает прямое изменение `main`.

## Контроль настройки

1. Открыть тестовый PR с намеренно падающей проверкой — Merge должен быть недоступен.
2. Попытаться выполнить прямой commit в `main` — GitHub должен отклонить операцию.
3. После зелёного `safety` объединить безопасный тестовый PR.
4. Убедиться, что push в `main` запустил повторный `Safety checks`.

## Откат

Откат приложения выполняется отдельным PR, который возвращает конкретный merge
commit и проходит тот же `safety`. Force push, удаление истории и прямой обход
`main` запрещены. При аварии production сначала отключается затронутая функция;
история и данные сохраняются. Временное снятие ruleset допускается только владельцем
после зафиксированного инцидента и с немедленным восстановлением правил.
