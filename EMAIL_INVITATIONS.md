# Отправка приглашений по почте — подготовка

Статус: не подключено и не опубликовано. Текущий реестр продолжает только готовить приглашение для ручной отправки.

Проверено: действующая studkab-requests v3 использует generate_link, но не отправляет email. PASSWORD_ACCESS.md фиксирует отсутствие SMTP. Доступный коннектор не предоставляет чтение/изменение SMTP и секретов отправителя. Текущее фактическое состояние SMTP в панели провайдера независимо не подтверждено.

Подготовлен внутренний модуль invitation-mail.mjs с внедряемым SMTP-транспортом: фиксированный нейтральный отправитель, один получатель, серверное формирование ссылки и текста, различение принятия письма сервисом, отказа и неизвестного результата. Без настроек отправителя ссылка не создаётся. Это подготовка, не законченная интеграция.

До подключения интерфейса и публикации необходимо:
1. Выбрать подтверждённый адрес отправителя и доступный почтовый сервис. Учётные данные сохраняются в секретах сервера, не в GitHub и не в чате.
2. Проверить SMTP из среды выполнения; TLS обязателен, журналы содержимого писем отключены. Сведения: https://nodemailer.com/smtp и https://supabase.com/docs/guides/functions/secrets.
3. Подключить модуль за существующей проверкой подтверждённого исполнителя; переиспользовать общий шаблон инструкции. Добавить постоянный журнал операций и защиту от повторного нажатия до разрешения отправки.
4. Добавить кнопку отправки на почту и отдельную ручную передачу. Не показывать «доставлено» по одному SMTP-подтверждению. Не повторять автоматически отправку с неизвестным результатом.
5. Проверить одно согласованное тестовое письмо, первый вход и повторный вход; без реальной доставки этап не принимать.

Нужное решение владельца: какой адрес будет отправителем и где он обслуживается. Пароль обычного почтового ящика запрашивать в чате нельзя.
